# Proof 07, durable state and corpus graph

## 1. The claim

A durable task killed mid-run resumes from its last checkpoint on the ledger
with nothing produced before the kill lost, and the ledger shows the seam: an
unsealed run that stops at a checkpoint and a second run that opens declaring
the checkpoint it restored. Separately, a persisted corpus graph answers a
symbol query reading a fraction of the bytes a flat scan reads, and when the
graph is stale it loses to the flat scan until an expiry re-read recovers the
answer, both measured.

## 2. The attack

Executed by `docs/proof/07-run.sh`, `tests/durable.rs` and the `src/graph.rs`
unit tests.

1. Run a five-file durable audit, killed after two files by
   `process::exit(137)` with the run unsealed, exactly as a killed process
   leaves it. Resume must restore the two pre-kill results from the ledger and
   finish the remaining three; the seal must cover all five, and the ledger
   must show which run died and which restored it. One pre-kill checkpoint is
   then proved included offline, network denied.
2. Build a corpus graph over twelve files and query a symbol two ways. Fresh,
   the graph must agree with the flat scan and read far fewer bytes. Then add
   a symbol to a file after indexing: the stale graph must lose (miss the
   hit), the flat scan must find it, and the graph's expiry re-read must
   recover it, with the extra bytes counted.

`tests/durable.rs` pins the resume arc with a real drop-without-seal and
asserts two `run.open` events, exactly one `run.seal`, the restored
checkpoint id, and offline verification. `src/graph.rs` pins the fresh
agreement, the stale loss, and the expiry recovery.

Reproduce with:

```
cargo build
zsh docs/proof/07-run.sh
```

## 4. What surprised me

**The floor finally moved, and the thing that moved it was refusing to hold
state in a field.** Because a checkpoint carries the whole accumulated result
vector rather than a cursor, resume needs nothing but the ledger: it reads the
last checkpoint, and the two pre-kill results are there, byte for byte. The
kill is real (`process::exit(137)`, no destructor runs, no seal), and the
resume is a different process reading a file. Overall conformance moves off 1
for the first time in seven slices, and the reason is that durability was
built as "the state was already on the append-only record before the crash",
not as a recovery routine bolted on after.

**The graph's loss is more convincing than its win.** The 30x byte saving on
a fresh query is the expected result and reads like a benchmark. The
interesting output is the stale query returning zero hits while flat returns
one, printed as an accuracy failure in the tool's own voice. A retrieval
layer that only ever reported its wins would be untrustworthy exactly where it
matters; the expiry re-read then recovers the answer at a measured cost
(1929 to 6762 bytes), which is the real shape of the tradeoff: the graph is
cheap when fresh, correct when it pays to re-read, and wrong-and-cheap in
between, and the run says which.

**The seam is visible without any special kill marker.** I expected to need a
`seq` gap or an explicit "aborted" event to show the kill. Neither was
needed: a run that opened and never sealed is the kill point, derivable by set
difference over `run.open` and `run.seal` run ids, and the resume's
`restored_checkpoint` field points straight back at where it picked up. The
append-only log plus the seal discipline already encode the seam; the `seam`
function just reads it.

## 6. What is still a guide

- **A mid-step kill loses the in-flight step.** Only completed steps
  checkpoint, so a process killed while step N is running resumes at N, redoing
  it. For idempotent steps (read and hash a file) this is free; for a step
  with side effects it is not, and nothing yet marks a step idempotent.
  `[UNENFORCED]` `ci/step-idempotence-declared`.
- **Resume is manual.** `gantry durable resume` is run by hand. Nothing detects
  an unsealed run and restarts it; the orchestrator wiring that would is the
  join between this slice and slice 06, and it is not built.
- **Checkpoints carry the full state each time.** Every checkpoint writes the
  entire accumulated result vector, O(n^2) bytes over a task. Fine at the
  proof's scale, a real cost at length; delta encoding is the upgrade, noted
  with a `ponytail:`-style ceiling in the code.
- **The graph is a token index, not a graph.** Nodes carry symbols and hashes
  but there are no edges yet, so "traverse instead of re-read" is really
  "consult the index instead of re-read". Reference edges and transitive
  queries are the next increment; the losing case and the expiry mechanism
  hold regardless.
- **Staleness is checked by re-reading, which costs the read.** Expiry
  verification reads every candidate file to compare hashes, so on a large
  corpus the `verify_stale` path approaches the flat cost. A cheaper staleness
  signal (mtime, a watch) is the missing piece; the hash comparison is correct
  but not cheap.
