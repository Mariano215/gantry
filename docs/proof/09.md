# Proof 09, skills, sub-agents, templates

## 1. The claim

A skill package is resolved or refused, never published on the strength of
its title: broken metadata, a step the manifest references but that no longer
exists, and a signature that no registered key verifies each fail at resolve
time, before any run consumes the skill, and the refusal is on the ledger.
Delegation to a skill can only narrow the parent's scope, never widen it.

## 2. The attack

Executed by `docs/proof/09-run.sh`, `tests/skills.rs` and the `src/skills.rs`
unit tests, against the tracked signed fixture
`docs/proof/fixtures/skill-repo-audit`.

1. Empty the manifest's description and resolve: the resolver must refuse and
   must not substitute the id or title for the missing field.
2. Delete a step the manifest references (`scan`) and resolve: it must fail
   naming the missing step, at resolve time, not when an agent reaches that
   step mid-run.
3. Tamper with the manifest after signing: the signature must no longer
   verify, and the skill must be refused, not silently downgraded to
   unsigned.
4. Delegate the skill from a parent that holds its scope (narrows fine) and
   from a parent that does not (must refuse to widen).

Reproduce with:

```
cargo build
zsh docs/proof/09-run.sh
```

## 4. What surprised me

**The unverifiable signature being worse than no signature took a second to
get right.** The first instinct is a three-state result: verified, unsigned,
or invalid, with invalid treated as a warning. But a manifest that carries a
signature is making a claim, and a claim that fails to check is a lie, not an
absence. So the resolver refuses an unverifiable signature outright and only
returns "unsigned" when there is genuinely no signature to check. The
distinction matters because an attacker who tampers with a signed skill wants
exactly the lenient behaviour: strip the guarantee down to "well, it is at
least unsigned" and slip through. Refusing closes that.

**Resolve-time failure is the whole value, and it is almost anticlimactic to
implement.** The dangerous version of a missing step is the one discovered
three steps into a run, with side effects already committed and a half-done
task on the ledger. The safe version is a directory existence check at
resolve time. The entire slice is the discipline of doing the cheap check
early rather than the expensive discovery late, and the proof is that the
refusal happens before a single step runs.

**The scorer immediately credited the new telemetry, which closed the loop
from slice 08.** Proof 08 left primitives 8 and 9 at N/A. This slice emits
`skill.resolve`, and re-scoring the resolution ledger shows primitive 09 at
3 without touching the scorer or its rules. The rubric-as-data design meant a
new layer's evidence was scored the moment it appeared, which is what
"scoring rules ship as re-runnable data" was for.

## 6. What is still a guide

- **The key registry is per-call, not managed.** `skill resolve` takes the
  public key on the command line. A managed registry of signing keys, with
  its own rotation and revocation, is the next increment. `[UNENFORCED]`
  `ci/skill-key-registry` in `CLAUDE.md`. *Closed after this proof:
  `config/skill-keys.json` is the tracked registry, loaded by
  `KeyRegistry::load`, which refuses the whole file on a corrupt key or an
  ownerless entry. Rotation and revocation remain manual edits to the
  tracked file.*
- **Templates are named but not built.** The slice title includes harness
  templates for common service topologies; this slice delivered skills and
  delegation. A template as a validated bundle of policy, sensors and
  providers is unbuilt, and the proof does not claim it. *Closed after this
  proof: `templates/laptop` is the tracked bundle and `gantry template
  validate` loads every part through the same validators the runtime uses,
  so a shadowed rule or a sensor with no fix refuses the whole template;
  `gantry template init` copies a validated bundle into a new harness and
  never overwrites.*
- **Delegation is a scope check, not a running sub-agent.** `delegate` proves
  the granted set is a subset; it does not yet spawn a sub-agent that runs
  under that narrowed grant and emits its own `subagent.spawn` and run events.
  That run telemetry is what would move primitive 08 past 3. *Closed after
  this proof: `gantry skill run` opens a delegated broker run that records
  `subagent.spawn` and denies an out-of-grant call at the chokepoint with
  rule `r-delegation` (`tests/broker.rs`,
  `a_delegated_grant_narrows_the_chokepoint`).*
- **A resolved skill does not yet execute.** The resolver validates and
  records; nothing runs the resolved steps through the broker under the
  delegated scope. Wiring resolve to execution is the join between this slice
  and the orchestrator, and it is left for after the nine. *Closed after this
  proof: `gantry skill run` resolves against the managed registry (refusing
  a broken package before anything executes), narrows the grant, and reads
  each step through the broker chokepoint; the self-audit ledger now scores
  primitives 08 and 09 from that telemetry (`docs/proof/08-run.sh`).*
