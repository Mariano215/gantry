# Proof 08, conformance scorer and console

## 1. The claim

Gantry scores itself from its own telemetry: `gantry score` reads a ledger,
scores each of the twelve primitives from the events actually present, marks a
primitive N/A when its base evidence never appears, and reports the overall
level as the minimum across scored primitives. The scoring rules are data, the
score is re-derivable by anyone holding the ledger, and the published number
is low because telemetry, not the profile name, decides it.

## 2. The attack

The adversarial case for a scorer is the flattering lie: a score read from the
profile name or a config value rather than from what ran, or an average that
hides a weak layer behind strong ones. The proof is that the scorer cannot do
either.

`docs/proof/08-run.sh` builds one self-audit ledger by exercising the layers
(a model call, a denied tool call, a rejected registration, an allowed
tainted call, a passing sensor and a broken sensor, twenty orchestrated runs
that earn a promotion, a killed-and-resumed durable task), then runs `gantry
score` over it. The rules live in `config/scoring.json`; every predicate is a
statement about events. `src/scorer.rs` unit tests pin that an absent
primitive scores N/A not 0, that a seam lifts observability, and that the
overall is the minimum, not the average.

Reproduce with:

```
cargo build
zsh docs/proof/08-run.sh
```

## 4. What surprised me

**The scorer scored the platform lower than its own proof documents did, and
that is the scorer working.** Proof 07 argued context management (primitive 3)
had reached 3 on the strength of the corpus graph. The scorer gives it 2,
because the graph retrieval is not emitted as events, and the scorer only
credits telemetry. So the overall level lands at 2, one below the proof-07
prose. This is the exact failure mode the slice exists to prevent, caught
against its own author: the earlier document reasoned about a capability, the
scorer measured the record, and the record is thinner. The fix is not to argue
the number up but to ledger the graph work, which is now a named gap.

**N/A is doing more work than any score.** Primitives 8 and 9 are N/A, not 0,
because their base evidence never appears. A zero would say "sub-agents are
broken"; N/A says "sub-agents were never exercised on this ledger", which is
true and different. The overall level ignores N/A entirely, so building slice
09 will add two scores that can only lower or hold the overall, never inflate
it. A scorer that scored absent layers as zero would make every unfinished
system look actively broken rather than incomplete.

**Scoring is itself an event, and that closed a small loop.** The
`score.snapshot` is appended to the ledger it scored, so the act of the
platform observing itself is on the same append-only record as everything it
observed, and the ledger still verifies afterward. The scorer ignores
`score.snapshot` when scoring, so this does not recurse, but a future score
can now see when the platform last scored itself and what it said.

The scorer is the primitive-08 service, so this slice's delta is the primitive
it implements plus what its own output reports. The table below is the
before/after of building the scorer; the scorer's telemetry-derived numbers
(section 3) are the same values, now produced by a running service rather than
by hand.

| Primitive | Before | After | Evidence |
|---|---|---|---|
| 08 Conformance (scorer) | 2 | 4 | The rubric is a running service reading telemetry: twelve scores, N/A where unexercised, overall as the minimum, every score linked to a sample event, rules shipped as re-runnable data. Not 5: the rules are hand-written and not themselves scored, and the console is generated, not yet served by the binary. |

The overall level of the platform, by its own scorer, is **2**, and it is
published in `README.md` with the low number included, which is the proof
gate for this slice. The other eleven primitives' scores are the scorer's
output, not a separate hand-assessment; the earlier proofs' hand tables and
the scorer now disagree by design on primitive 3 (hand said 3, telemetry says
2), and the telemetry wins.

## 6. What is still a guide

- **The graph is not ledgered, so it does not score.** Context management sits
  at 2 because the corpus graph emits no events. Emitting a `graph.query`
  event with the byte and accuracy delta would let the scorer credit it; until
  then the measured capability and the scored capability differ, on purpose.
  `[UNENFORCED]` `ci/graph-emits-telemetry`. *Closed after this proof:
  `gantry graph query` now ledgers each retrieval as a `graph.query` event
  with `bytes_read`, `index_bytes` and `stale_reread`; scoring rules
  `scoring-2` credit level 3 from it. Re-running `docs/proof/08-run.sh`
  (which now includes a graph leg) scores primitive 3 at 3 and overall at 3,
  and the ledger still verifies.*
- **The scoring rules are hand-written and unscored.** `config/scoring.json`
  is trusted data. Nothing checks that a level's predicate actually requires
  what its evidence string claims, so a sloppy rule could credit a level on
  weak evidence. A rule that a sensor cannot fail applies to sensors, not yet
  to the rules that score them. `[UNENFORCED]` `ci/scoring-rules-reviewed`.
  *Partially mechanised after the nine: `tests/scoring.rs` fails the build
  when a predicate references an event kind the schema does not document
  (a dead rule that could silently cap a primitive forever), when a
  primitive declares duplicate levels, or when a level has no evidence
  string. Whether a predicate requires what its evidence claims remains
  human review.*
- **The console is generated, not served.** `gantry score` writes a static
  HTML file; the plan's "static assets the binary serves" is one HTTP handler
  away and not built. The asset is real, the server is not.
- **Overall N/A is possible and unhandled downstream.** If a ledger exercises
  no primitive, the overall is N/A. The scorer reports it honestly, but no
  consumer yet decides what an all-N/A score means for a gate.
