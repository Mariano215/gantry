# Proof 13, instruction lifecycle telemetry

## 1. The claim

Primitive 1 was capped at 3 because `instructions/pack.md` was pinned by
hash on every `run.open` but nothing recorded whether a change to it had
been reviewed: version pinning proves what ran, not that anyone looked at
it. The `instruction-lifecycle` sensor closes that gap: it fails when the
pack's hash is not in `config/instruction-reviews.jsonl`, that fail verdict
is a ledger event, and `config/scoring.json` now credits level 4 from it.
The score moves only when the pack itself changes without a matching
review, never from an unrelated edit.

## 2. The attack

Executed by `docs/proof/13-run.sh` against the tracked sensor
`templates/laptop/config/sensors/instruction-lifecycle.json`.

1. Baseline: gate the sensor against a working copy of the real
   `instructions/pack.md`, whose hash is already in
   `config/instruction-reviews.jsonl`. Must pass, and primitive 1 must stay
   at 3.
2. Change the pack (append a line to the working copy) without touching the
   review record. Must fail, naming the fix, and primitive 1 must reach 4.
3. Control: leave the pack copy untouched and instead write an unrelated
   prose file. The pack's hash has not changed, so the sensor must still
   pass and primitive 1 must stay at 3, proving the score reacts to the
   pack's content, not to activity near it.
4. Confirm the sensor is live: it must reject its own negative control
   (unreviewed placeholder content), or its verdicts would be worthless.

Reproduce with:

```
cargo build
zsh docs/proof/13-run.sh
```

## 3. What happened

Workdir `/tmp/gantry-proof13.TqgcyR`. All output verbatim.

Baseline, reviewed content passes, score stays at 3:

```

```

Attack, an unreviewed change fails and the fix names the action:

```

    instructions/pack.md changed without a matching review record. Review the new content, then append a line to config/instruction-reviews.jsonl with its current hash (shasum -a 256 instructions/pack.md), a reviewer, and a date.
sealed at ledger size 3
gate did not pass, exit=1
primitive 1 score: 4 (expected 4: the sensor caught it)
```

Control, prose elsewhere does not move the score:

```

sealed at ledger size 3
primitive 1 score: 3 (expected 3: the pack itself never changed, so the sensor never fires)
```

## 4. What surprised you

The scorer's predicate schema (`Pred` in `src/scorer.rs`) is one event kind
plus a single JSON-pointer/equals pair; there is no way to require two
fields on the *same* event ("sensor is instruction-lifecycle" AND "verdict
is fail") without either changing that struct or finding one field whose
value already encodes both. `SensorVerdict.message` does exactly that: it
is `Some(fix)` if and only if the verdict is a fail, and `fix` is this
sensor's own text, so matching `/message` against the exact fix string
identifies "this sensor, this outcome" in one predicate with zero code
changes to `src/scorer.rs` or `src/sensor.rs`. The coupling is real (the fix
string in `templates/laptop/config/sensors/instruction-lifecycle.json` and
the `equals` value in `config/scoring.json` must match byte for byte) but
both files are mine to keep in sync, and it is no more fragile than any
other string the scoring rules already depend on.

The sensor's `check` command reads `config/instruction-reviews.jsonl` by a
path relative to the process's working directory, not relative to the
staged `{target}` file. The sandbox denies writes outside its own workdir
but allows reads everywhere (`src/sandbox.rs`, `(allow default)` minus the
write and network denials), so this works, but it means the sensor is only
correct when gantry runs from the repository root, exactly like every other
sensor and CLI subcommand that reads `config/policy.json` or
`instructions/pack.md` by a bare relative path.

## 5. Conformance delta

Primitive 1 (Instruction): moves from a hard cap at 3 ("instruction pack
version-pinned; no lifecycle telemetry") to reachable level 4 ("a lifecycle
sensor caught an unreviewed change"), evidenced by
`config/scoring.json` and exercised in `docs/proof/13-run.sh`. This is a
per-ledger score: a ledger that never runs the sensor, or runs it only
against reviewed content, still reports 3, which is correct: level 4 is
earned by catching a real unreviewed change, not by the sensor merely
existing. `tests/scoring.rs`
(`every_scoring_predicate_kind_is_a_documented_event_kind`) already passes
because `sensor.verdict` was documented in `docs/EVENT-SCHEMA.md` before
this slice (primitive 10 uses the same kind). Overall level unaffected: it
is the minimum across primitives, and this slice only raises a ceiling on
one of them.

## 6. What is still a guide

`config/instruction-reviews.jsonl` is appended to by hand: nothing in this
slice enforces that a human (or an agent under a named actor) actually
reviewed the content before adding a line, only that a line with the
matching hash exists. A reviewer could append the current hash without
reading the diff, and the sensor would report clean. Catching that would
need the review record to carry an attestation the ledger's actor-key
registry verifies (`config/actor-keys.json`, already used for ledger
attestations since the post-nine gap work) rather than a plain JSON line,
which is future work, not marked `[UNENFORCED]` in CLAUDE.md because
CLAUDE.md makes no claim about review authenticity, only about lifecycle
telemetry existing, which this slice enforces.
