# Proof 01, evidence ledger

## 1. The claim

An append-only Merkle ledger (RFC 6962 construction, per-append ed25519 signed
tree heads) now exists as running code, and it detects one flipped byte
anywhere in its history, names the damaged entry and the divergence point, and
proves a single event's inclusion to a verifier holding nothing but the
envelope, the proof, one signed head and the ledger public key, with the
network denied.

## 2. The attack

Five attacks against a 8-event ledger built by `docs/proof/01-run.sh`, which
is the committed, re-runnable fixture. The ledger content is a transcription
of a realistic run (open, tool request and result, a policy denial, a sensor
block, an approval, the drift report, seal) under event schema v2. Every
attack is a real mutation of the files on disk, made by the script, followed
by `gantry ledger verify`.

1. Flip one byte of historical entry 3 (a digit of its `ts`, inside the
   stored envelope line).
2. Flip one byte of the newest entry, which the `prev_hash` chain cannot see
   because nothing chains after it.
3. Truncate `events.jsonl` from 8 entries to 5.
4. Flip one byte of the newest entry and also delete the signed head that
   covers it, the attack that beat the verifier during review (finding 1
   below).
5. Delete a subject payload with no `retention.expire` event on record, then
   do the same expiry lawfully and verify again.

Then offline: verify an inclusion bundle for entry 4 in a directory containing
only `bundle.json` and `ledger.pub`, under
`sandbox-exec -p '(version 1)(allow default)(deny network*)'`, and verify a
tampered copy of the same bundle fails.

Reproduce with:

```
cargo build
zsh docs/proof/01-run.sh
```

## 4. What surprised me

**The proof script attacked the wrong layer, and the verifier caught the
author.** The first version of the attack script flipped bytes by searching
entry lines for `"verdict":"deny"` and `"outcome":"complete"`. Those strings
are not in the envelope lines at all: schema v2 moved every subject field
behind `subject_hash`, a change written hours earlier in the same session.
The searches returned -1, the arithmetic turned that into file offsets in
entries 0 and 7, and the script corrupted bytes it never aimed at. Every one
of those accidental corruptions was detected and named precisely. The lesson
is double: the verifier survived an attack its author did not intend, and the
author of the schema change could not keep it in mind for one afternoon,
which is the strongest argument this project has yet produced for machine
checks over memory.

**The reviewer's attack was better than mine.** An agent reviewing the diff
found that `verify()` checked every head that existed but never asked whether
the heads covered the log: tamper the newest entry, delete the newest head,
and verification passed clean. The existing last-entry-tamper test passed
while missing this, because it never touched `heads.jsonl`. The newest entry
is exactly the one an attacker wants, and it is the one entry the chain
cannot protect. Fixed by faulting on any uncovered tail; attack 4 is the
regression test.

**Two real implementation bugs never reached the working tree history.** The
`split_last` destructure was swapped in both proof reconstructors (compile
error), and consistency verification failed to fold the shared left subtree
into the reconstructed old root (caught by the property test at m=3, n=4).
Both were found by the first `cargo test` run. Neither would have been found
by reading the code, which reads plausibly in both versions.

**A sensor's documented scope silently reverted.** Proof 00 finding (h) was
resolved by narrowing the `ghost` sensor's scope, at the operator's
direction, to skip agent-facing paths (`/docs/`, `CLAUDE.md` and others).
When this slice tried to add its `[UNENFORCED]` marker to `CLAUDE.md`, the
sensor fired on that file's pre-existing dashes again: the running
`skip_path_substrings` no longer contained any of the five recorded entries,
most plausibly reset by a plugin update. The recorded configuration and the
running configuration diverged, nothing compared them, and the divergence was
found only because the sensor happened to fire. This is the permission-mode
drift of finding 00(a) again, one layer down, against the project's own
sensor. The recorded scope was restored and this paragraph is the report.

**The toolchain did not exist and the C compiler was an impostor.** The
machine had no Rust, and after installing it, the first build failed because
a dashboard tool named `cc` shadowed the system compiler in PATH. Neither
fact was declared anywhere; both were discovered by failure. A harness that
tracked its own environment declaration (primitive 12, again) would have
named both before the first command ran.

## 6. What is still a guide

- **Attestation verification.** The envelope carries an optional actor
  attestation and nothing can verify one, because no actor key registry
  exists. The verifier counts them and reports
  `attestations present but not verified` rather than passing silently, which
  is honest but is not enforcement. Marked `[UNENFORCED]`
  `ci/attestation-verify` in `CLAUDE.md`. *Closed after the nine:
  `ledger::verify_with_actor_keys` checks each attestation whose key id
  resolves to a key in `config/actor-keys.json`; a registered key that fails
  to verify is a fault, an unregistered key id is still counted and
  reported. Producers still emit no attestations (laptop default null), so
  the verified path is proven by `tests/ledger.rs`, not yet by runs.*
- **Prior-state replacement.** Replacing `events.jsonl` and `heads.jsonl`
  together with an internally consistent older state is undetectable by
  `verify()` alone. This is the known limit of any transparency log without
  head gossip or anchoring; the `ledger.anchor` event kind exists in the
  schema and nothing emits one yet. Covered by the existing
  `ci/ledger-append-only` `[UNENFORCED]` claim and lands with anchoring.
- **The six `ci/` checks claimed by `CLAUDE.md`** remain unimplemented. Two
  of them (`ci/offline-suite`, `ci/ledger-append-only`) now have code they
  could run against, which they did not have yesterday. Still zero CI.
- **`seq` gap reporting** is described by the schema (a gap is the signal a
  harness was detached) and the verifier does not yet report gaps. Deferred,
  not forgotten: it needs a per-run index the verifier does not build yet.
