# Proof 02, model gateway

## 1. The claim

Every model call in this repository now passes through one chokepoint,
`gateway::GatewayRun`, which appends a schema v2 `model.call` event to the
evidence ledger whether the call succeeds or fails, and the same two-turn
workload run against a frontier API, a cloud-hosted model, and a local model
on a loopback-only network produced three ledgers with byte-identical
envelope and subject key sets.

## 2. The attack

Six cases, all executed by `docs/proof/02-run.sh` (the committed,
re-runnable fixture) or by the test suite, none by reasoning:

1. The air-gap leg. The local run executes under
   `sandbox-exec -p '(version 1)(allow default)(deny network*)(allow network* (remote ip "localhost:11434"))'`,
   so the process has no route to anything but loopback.
2. Negative controls on that same profile: a curl to the Tailscale GPU box
   and a curl to `https://api.openai.com` from inside the sandbox. If either
   connects, the air-gap claim is theatre and the script exits 1.
3. A dead provider (`http://127.0.0.1:1/v1`, nothing listens on port 1). The
   call must fail, the failure must be on the ledger, and the ledger must
   still verify.
4. A provider key with no credit. Before the proof run, the configured
   OpenAI key returned HTTP 429 with a quota error body. This was not
   staged; it happened, and it exercised the exact path attack 3 tests, over
   a real TLS connection against a real provider.
5. Authority drift, live. The working tree's `.claude/settings.json`
   diverged from HEAD all session (the operator widened the allow list
   mid-session and chose to keep it uncommitted). Slice 00 and 01 recorded
   this class of divergence as a finding a human had to notice. This run is
   the test of whether the machine notices.
6. Offline inclusion. One event from the air-gapped leg, proved to a
   verifier holding only `bundle02.json` (1288 bytes) and `ledger.pub`,
   under `sandbox-exec -p '(version 1)(allow default)(deny network*)'`.

Key-exfiltration attacks (provider error bodies echoing the key, the key
appearing anywhere under the ledger directory, userinfo credentials in a
base_url) are pinned by the suite rather than the script:
`provider_error_never_leaks_the_key_onto_the_ledger`,
`key_bytes_never_reach_the_ledger` (which also asserts the Bearer header
did go out on the wire, so the test cannot pass vacuously),
`base_url_with_credential_is_rejected`, and `tests/invariants.rs`, which
fails the build if the HTTP client is referenced outside `src/gateway.rs`.

Reproduce with:

```
cargo build
zsh docs/proof/02-run.sh
```

The 429 body reached stderr for the human. On the ledger, the subject's

Attack 5, drift detection. Every event of every leg carries:

```

```

from `authority` in the envelope, computed by comparing the sha256 of the
working `.claude/settings.json` against the HEAD blob. The divergence that
proofs 00 and 01 could only report after a human noticed is now written by
the machine into every event it signs while the divergence is in force.

Attack 6, offline inclusion, network denied, no ledger directory present:

```

```

The suite stands at 35 tests plus clippy with `-D warnings`, all clean at
7e45569. The branch was built by an agent team under per-task adversarial
review: three tasks entered fix loops (a key-scrubbing security fix, two
deduplication findings), and the final whole-branch review produced five
findings that were all fixed and re-verified before this run.

## 4. What surprised me

**The final review caught the ledger lying before the ledger could make it
permanent.** The implementation hardcoded `authority.diverged: []`, meaning
"running config matches tracked declaration", while the actual working tree
diverged. Provider error bodies went verbatim into subjects on an
append-only record, where a proxy echoing request headers would have parked
secrets behind a retention-only remedy. The prompt hash resolved to no
stored artifact, an unopenable commitment presented as if under retention.
None of these were behavior bugs; all 32 tests passed. They were false
statements queued for an unretractable record, found only because a review
ran between "tests green" and "proof run". The fix for the first is why
attack 5 exists at all.

**The frontier environment failed first for a mundane reason and the
failure was the best fixture of the day.** The OpenAI key had no credit.
The 429 flowed through the exact error path the reviewer had forced to be
sanitised days earlier in session time, and produced a real, unstaged
demonstration: excerpt to the human, status plus hash to the record, run
honestly unsealed.

**An undeclared environment variable sent local commands to another
machine.** `OLLAMA_HOST=http://100.120.203.53:11434/v1` was exported in the
shell, so every `ollama` CLI command silently targeted the Windows GPU box
over Tailscale, and the `/v1` suffix broke them with an error naming
neither the host nor the cause. The local model pull only succeeded after
overriding the variable per-command. Nothing declared this variable; it was
discovered by failure, the same class of gap as proof 01's shadowed C
compiler, which also recurred (`cc` resolves to a dashboard tool; builds
need `CC=/usr/bin/cc` and the rustup toolchain path, since cargo is not on
PATH either). Primitive 12 keeps sending the same postcard.

**The reviewer defanged one finding and sharpened another in the same
paragraph.** The parked note said a query-string credential in `base_url`
could leak. The final reviewer showed that variant is harmless here, since
appending `/chat/completions` after a query string yields a URL that fails,
and that the userinfo form (`https://user:pass@host`) is the variant that
works and leaks. The fix rejects `@` at config load. The lesson: a caveat
written from memory of a risk class named the wrong member of the class.

## 6. What is still a guide

- **Drift detection covers one field.** `diverged` compares the settings
  file hash against HEAD. The running permission mode, the allow and deny
  lists as the host actually interprets them, and the instruction pack the
  host injects are all still asserted, not derived. `[UNENFORCED]`
  `ci/permission-mode-drift` stays in `CLAUDE.md`, now marked partially
  mechanised.
- **`ci/no-direct-sdk` is enforced, but by the test suite.** `CLAUDE.md`
  updated to name `tests/invariants.rs` as the enforcement. Since nothing
  forces the suite to run (no CI), the enforcement is only as strong as
  primitive 10's cap.
- **Prompt payloads are hash-only by decision.** The `prompt_hash` is a
  commitment with no stored artifact to open it against. Stated in the
  spec and in `src/gateway.rs`; storage under retention arrives with the
  broker slices. Until then an auditor can prove a prompt was fixed at call
  time but not read it.
- **Cost rates are config data.** `cost_in_per_mtok` values in
  `config/providers.json` were checked against the provider's price page
  once, by hand, this session. Nothing re-checks them; a stale rate
  produces a confidently wrong `cost_usd` on a signed record.
- **The missing-usage path is code-verified only.** A provider response
  without `usage` records nulls rather than fake zeros, but no test
  constructs that response. Noted by the fix-wave re-review.
- **The environment is still undeclared.** `OLLAMA_HOST`, the shadowed
  `cc`, cargo absent from PATH: three session-breaking environment facts,
  all discovered by failure, none declared anywhere a machine checks.
