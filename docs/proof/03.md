# Proof 03, tool broker and policy engine

## 1. The claim

Every tool call in this repository now passes through one broker that
evaluates the tracked, content-versioned policy to exactly one
`policy.decision` per call, executes nothing the policy did not allow, and
records request, decision and result on the signed ledger; a destructive
command is denied with the rule, policy version and identity named, and a
tool declared as "run any shell command" cannot be registered.

## 2. The attack

Seven cases, all executed by `docs/proof/03-run.sh` (the committed,
re-runnable fixture) or by the test suite, none by reasoning. No network is
needed anywhere in this proof.

1. The headline attack: `gantry broker call $L Bash "rm -rf /"`. The command
   must not execute, and the ledger must name the rule that fired, the
   policy version in force, and the identity.
2. The registry attack from the plan: publish a tool whose definition is
   `{"name": "shell.any", "description": "Run any shell command.",
   "inputSchema": {"type": "object"}}`. The registry must refuse it and
   record the refusal.
3. A credential file read, `gantry broker call $L Read "./.env"`, against
   the real `.env` in this repository.
4. An irreversible call under an allow rule: `git push origin main && touch
   $MARKER`. The policy has an explicit allow for `vcs.publish`, and the
   call must still block, because irreversible gates pre at every rung. The
   marker file is the executed-anyway detector.
5. Egress: `curl https://example.com` on the laptop profile.
6. A policy that lies refuses to load: one fixture with a deny rule shadowed
   by an earlier broader allow, one fixture with a post-gate capability
   whose rollback handle was deleted.
7. The honest one: the same destructive command with one extra space,
   `rm  -rf $WORK/victim`. This is expected to evade the glob and execute,
   and the point is that the record says so.

The suite pins the rest: `tests/broker.rs` asserts the exact event sequence
per call (`run.open`, two `tool.register`, `tool.request`,
`policy.decision`, `tool.result`, `run.seal`), that a held call never
executes, that an unregistered tool never reaches the policy, that the
tracked policy has host parity with `.claude/settings.json`, and the loader
refusals of case 6. Unit tests in `src/policy.rs` pin the gate table cell by
cell against the table in `docs/POLICY-SCHEMA.md`.

Reproduce with:

```
cargo build
zsh docs/proof/03-run.sh
```

## 4. What surprised me

**The slice 00 example policy cannot run anything.** The rules in
`docs/POLICY-SCHEMA.md` were written to illustrate shapes: one credential
deny, one egress deny, one docs-write allow, one default deny. Translated
literally into the machine policy, every ordinary read and every shell
command falls through to `r-default` and is denied, because default-deny
plus no allow rules denies everything. The evaluator forced what the prose
never had to state: a first-match-wins default-deny policy needs an
explicit allow rule per capability, or the capability list is decoration.
The tracked policy gained `r-read-repo`, `r-shell` and `r-publish` to
become runnable at all.

**The interesting denial is the one the rule author never wrote.** Attack 4
has an allow rule for `git push`, and the call still blocked, because the
verdict is derived from rung and effect, not written by the rule. Design
constraint 2 of the policy schema did exactly what it promised, and the
resulting message (approval required, no mechanism until slice 06) is the
system being honest about a gate it cannot yet open rather than quietly
downgrading the gate to allow.

**The shadowed `cc` recurred a third time and finally became a sensor.**
Proofs 01 and 02 both record builds broken by a dashboard tool named `cc`
shadowing the system compiler. This session it broke the build again, at
link time and then again inside ring's build script. Per the working
agreement (a second identical failure means a sensor, not a third repair),
the fix is now `.cargo/config.toml` pinning `linker` and `CC` to
`/usr/bin/cc`, committed. The build no longer depends on PATH order, and
the recurring postcard from primitive 12 stops.

**One extra space defeats the headline rule, and that is the true reading
of this slice.** Attack 7 deleted its victim through the same broker that
denied attack 1, because `rm  -rf` does not match `rm -rf *`. Pattern
rules on command strings are tripwires for the honest and the clumsy, not
walls. The wall is the slice 04 sandbox; until then the policy file itself
declares `isolation: none`, and the proof document demonstrates the evasion
rather than hoping nobody notices it.

## 6. What is still a guide

- **The destructive-command rule is a tripwire.** Attack 7 is the standing
  demonstration. The enforcement floor for shell is the slice 04 sandbox;
  until it lands, `shell.exec` at `write.local` is an optimistic
  declaration that an unsandboxed process does not honour.
- **Review obligations are counted, not consumed.** The seal refuses to say
  clean while reviews are outstanding, but no review record kind exists yet
  to discharge one. Arrives with the sensor bus and orchestrator slices.
- **Holds cannot resolve.** `obligation: approval` is recorded and the call
  blocks forever. Honest, but the approval event of slice 06 is what makes
  a hold a gate rather than a wall.
- **Taint is recorded, not propagated.** A tainted tool result feeding a
  later model call is not yet marked in the `model.call` event. The
  plumbing between broker and gateway is a later slice.
- **Two policy version schemes coexist.** `gantry run` (gateway) still pins
  the byte hash of `docs/POLICY-SCHEMA.md`; the broker pins the computed
  content version of `config/policy.json`. One should subsume the other
  when the gateway starts consulting the policy engine.
- **MCP is the data shape, not the wire.** The registry stores and refuses
  MCP-form definitions, but no external MCP server can connect yet.
- Remaining `[UNENFORCED]` markers in `CLAUDE.md`: `ci/permission-mode-drift`
  (partially mechanised since slice 02), `ci/attestation-verify`, the
  profiles-never-lie scorer rule (slice 08), and the dependency-note rule.
  The three policy checks this slice enforced (`ci/policy-shadow`,
  `ci/policy-rollback`, `ci/policy-host-parity`) are marked enforced, with
  the standing caveat from proof 02 that enforcement by the test suite is
  only as strong as the missing CI.
